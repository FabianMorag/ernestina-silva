# React Router navigation
Objective: replace the manual `window.location` routing in apps/web with react-router while keeping every current URL and page.
Branch: feat/tournament-admin. Delivery: single-pr (separate semantic commits form one reviewable feature). Runner: pnpm.
Client-only: apps/web stays a static SPA; no server code is added.

## Specs
- S1: "vamos con react-router". Use react-router for every web route. Existing URLs keep their current page: `/` home; `/partidos` matches; `/campeonatos` championships; `/admin` and `/admin/campeonatos` admin championships; `/admin/jugadores` players; `/admin/equipos` teams; `/admin/partidos` admin matches; query `?campeonato=<id>` selects a championship on `/partidos` and `/admin/partidos`. Unknown `/admin/...` shows the admin not-found; any other unknown path shows the public not-found.
- S2: "esta es una app cliente, no tendremos servidor, por las dudas". The web app stays static: no server code in apps/web. Deep links work only when the host serves `index.html` for unknown paths; document that in the README. No host rewrite config is added (decision pending, see Log).
- S3: internal links use the router (`Link`), so moving between pages does not reload the document, and back/forward work. Search-param state stays synchronized with the URL. This is the consequence of S1, not a new feature.
- S4: "Recuerda separar las rutas en componentes siguiendo buenas practicas". The route table renders dedicated route components (public and admin route shells); route-specific responsibilities stay outside the application bootstrap, and shared page data/UI is reused instead of duplicating the existing screens.
- S5: "haz los commit semanticos". Commit the completed router change in clear Conventional Commit units.
