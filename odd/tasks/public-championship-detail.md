Objective: present real championship groups, player standings, knockout bracket, and match history in the public site.
Branch: `feat/tournament-admin`. Delivery: semantic local commits without a line cap (`exception-ok`); no push. Runner: pnpm.

## Specs
- S1: Use the supplied four-panel tournament image as visual inspiration for the public detail: "ahora si creo que podemos avanzar con la visual de las llaves y los grupos, etc [Image #1] nos basamos un poco en esta visual entonces recuerda que podemos usar motion". Do not reproduce its fictional teams, standings, status, or future fixtures.
- S2: Rank players and display their assigned team: "jugadores mostrando su equipo". Points: three for a win, one for a draw, zero for a loss. Tie-break by goal difference, goals scored, then player name: "exacto, vamos con eso".
- S3: Show recorded group and league results separately from knockout results. A group table must use only matches explicitly assigned to that group; the model does not assign a zero-game participant to a group. An unassigned match must not be silently included in a group table.
- S4: Build the knockout display from recorded `knockoutRound` and `knockoutSlot` values. Do not infer unrecorded participants, matches, winner progression, or a champion. A legacy knockout match without placement needs an honest separate presentation.
- S5: Preserve the existing public championship list and match-history URLs while adding a direct public championship detail route and a useful link from the list. Handle loading, missing championship, empty data, and API errors.
- S6: Use responsive, keyboard-accessible presentation inspired by the reference, with mobile-safe bracket/table handling. Motion is optional and must communicate a real user interaction or data transition; support reduced motion.
- S7: The user asked for implementation through Pi CLI with `opencode-go/claude-haiku-5-5` and explicitly authorized the already-configured OpenCode Go session. Do not push, open a PR, merge, or modify unrelated local edits.
