# Public home view (portada)
Objective: give `/` its own public landing content so it stops duplicating the `/campeonatos` list, using only facts the public API already exposes.
Branch: `feat/tournament-admin`. Delivery: semantic local commits without a line cap (`exception-ok`); no push. Runner: pnpm. Slice boundary: this feature is the single work-unit commit `426c56b`; the line cap stays waived by this delivery line. Public view only: no API, Prisma schema or admin changes.

## Specs
- S1: User request verbatim: "tenemos contenido inneecsariamente duplicado, tanto el nombre de la web \"Inicio\" y \"campeonatos\" nos llevan al mismo punto, quizas eliminamos uno". Scope clarification verbatim: "yo me referia a la vista publica en todo caso".
- S2: Chosen option verbatim: "Convertir / en portada", with the offered preview verbatim: "`/` = portada nueva: - campeonato en curso + ultimo resultado - accesos a Campeonatos y Partidos - `/campeonatos` = listado (como hoy)".
- S3: No recorded fact may be invented. The public surface exposes no championship status and no match date: `Championship` has only `id`/`name`, `GET /tournament/championships` orders by `name asc`, and the public `Match` payload carries no `playedAt`/`createdAt`. Therefore the home must not present a "campeonato en curso", a fixture schedule, or a "most recent championship". "Último partido registrado" is allowed only as the first item of `GET /tournament/matches`, whose server contract is `orderBy: { createdAt: 'desc' }` (record time, not kick-off time), and its copy must say registrado/cargado, never jugado.
- S4: `/campeonatos` keeps rendering the championship list exactly as it works now, and `/partidos` keeps the match history with its `?campeonato=` filter. `/`, `/campeonatos`, `/campeonatos/:id` and `/partidos` keep their current URLs and behavior (public-championship-detail S5 stays satisfied).
- S5: The home links to the two listings and to the detail of the championship that owns the most recently recorded match, with loading, empty and API-error states handled like the other public pages.
- S6: The nav keeps `Inicio`, `Campeonatos` and `Partidos` once `/` is a different page, since the duplication S1 complained about was the two links resolving to one page. Motion stays CSS-only and reduced-motion safe.
- S7: The count label and accessible listing names introduced earlier (`publicCountLabel`, `publicListingLabel`) keep working for both listings; the home is not a listing and does not reuse their chip.
